Adaptive and restartable Gaia retrieval validation

Status: Bounded split, stop, resume, and corruption-recovery test passed Date: 2026-07-18 Gaia release reference: 2023A&A...674A...1G, DOI 10.1051/0004-6361/202243940

Plain-language workflow

Before downloading a large galaxy-centered region, the workflow asks the Gaia archive only for the number of entries in that region. If the measured number is larger than the declared safe size for one download, the north-south coordinate range is divided in half and both halves are counted. This repeats until every final sky strip is small enough.

A checkpoint is the saved source file for one completed strip plus a small metadata file recording its expected row count, archive-query hash, retrieved row count, and source-file hash. Both files are written through temporary files so an interrupted write cannot masquerade as a completed download.

When a run restarts, every existing checkpoint is verified. A checkpoint is reused only when its query, expected count, file hash, row count, and source identifiers remain valid. Missing, incomplete, changed, or corrupted files are downloaded again. Successfully verified files are not queried again.

Bounded live validation

The validation uses the same 0.2-degree-radius NGC 4698 circle and 500-entry reference as the earlier partition test. A test-only limit of 130 entries per strip forces the workflow to measure and divide the circle adaptively. It creates six final strips containing 82, 71, 83, 70, 79, and 115 entries.

The first retrieval is deliberately stopped after saving two strips. A new retrieval instance then loads the saved plan, verifies and skips those two strips, and downloads only the remaining four. The two original files retain exactly the same hashes.

After that successful restart, the validation deliberately changes the final saved strip. A third retrieval detects the hash mismatch, downloads only that damaged strip again, and skips the five intact files. The final combined table contains 500 unique Gaia source identifiers and matches the independent reference exactly.

All 15 checks pass in 21.68 seconds. The validation queries only source_id, sky position, and G magnitude; it does not apply the UCD selector.

Production contract and remaining work

The 130-entry limit is intentionally small so the bounded test exercises splitting. It is not a production archive limit. The production safe size must be measured using the full set of Gaia columns required by the frozen selector. The reusable retriever accepts that full column list; its query hash invalidates checkpoints if the requested columns or any query condition changes.

A production run must preserve:

  • the complete measured split plan before source retrieval begins;
  • one atomic source and metadata checkpoint per final strip;
  • explicit complete, incomplete, failed, and recovered states;
  • exact source-identifier uniqueness after combination; and
  • the immutable run configuration, Gaia release, selector input columns, query hashes, and output hashes.

A follow-up full-column benchmark directly measured 5,000 rows three times and 10,000 rows once. The 5,000-row results had identical source identifiers, query times of 1.948628--1.976649 seconds, and serialized sizes of 1,027,468 bytes. The provisional development checkpoint limit was therefore 5,000 rows. A subsequent three-field test validates full-column restart behavior for one unsplit and two split cases and freezes the 5,000-row per-strip limit for development and pilot runs. The subsequent spherical area component maps verified completed strips to each ring's successfully queried and missing area, then subtracts the union of explicit masks. See docs/radial_ring_area_accounting.md.
