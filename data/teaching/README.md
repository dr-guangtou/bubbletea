# Versioned teaching data

## Current Part I packet: version 2

The current lesson is [A Galaxy in Disguise](../../docs/teaching/README.md).
The one-file student deliverable is
[ucd_investigation.html](../../docs/teaching/ucd_investigation.html).
It embeds 37 gallery objects, 74 DR11 JPEGs, and 21,118 Task 2 catalog rows.

- `ucd_course_packet_v2.json`: neutral Task 1 observations, labeled demonstration
  context, image request/digest records, and compact Task 2 rows with exact string
  Gaia identifiers and unrounded numeric values; missing measurements remain null.
- `instructor/part1_reference_key_v2.json`: separate Task 1 classes, full reference
  provenance, source-file hashes, curation decisions, role reservations, evidence
  notes, and grading policy. Never embed this key in the student file.
- `instructor/part1_image_reviews_v2.json`: explicit visual/evidence notes for all
  37 pairs, hashes of inspected images, and reasons for rejected gallery choices.
  This is agent-assisted teaching preparation; the instructor approved classroom
  finalization on 2026-10-14. It is not scientific confirmation of a source.
- `instructor/part1_selection_trial.json`: instructor-only bounded range-cut trial,
  frozen packet hash, evaluated grid, exact counts/F1, and all/none/one-object
  controls. Generated by `benchmark_part1_selection.py`; not a student preset.

The 2026-10-14 interface revision uses submission schema `bubbletea_answers_v3`
with this unchanged version 2 data packet and its original digest. Galactic
coordinates on the gallery cards are derived at build time from the saved ICRS
positions using Astropy. They do not alter the scientific input or frozen packet.
Older same-packet v2 answers retain their classifications, trial history, and
old final choices on import; the student then chooses one new final selection.

Task 2 contains 20,000 stars, 121 approved UCD references, 391 spectroscopic QSOs,
and 606 unconfirmed candidates. The latter are not scored. Apply the five current
reliability exclusions and the 13-object later source-status exclusion; preserve
the latter in the candidate pool. Development features, not reserved scientific
validation features, supply the literature and QSO measurements. The already-public
M60 demonstration comes from the v1 teaching packet. No research inputs are changed.

The external SDSS stellar parent has 79,369 exact, distinct Gaia IDs; its query,
matching method, and checksum are in
`data/literature/benchmarks/spectroscopic_stellar_reference_manifest_v3.json`.
After reserving 12 gallery stars, 79,357 fall in the comparison magnitude interval
11.26291847229004–21.75798797607422. Select 20,000 by sorting the SHA-256 of
`bubbletea_part1_v2:` plus the string identifier. Task 2 has no stellar selection
by astrometry, color, flux excess, or image quality. The small introductory gallery
is deliberately clearer and magnitude-matched; its stellar motion criterion is
recorded separately in the instructor key, not imposed on Task 2.

Task 1 presentation uses the independent hash prefix `presentation_order_v2:` so
parent sampling does not determine class blocks in the displayed order. Gaia IDs
never pass through floating point. Some FITS SDSS spectrum IDs use signed 64-bit
storage; convert negative stellar IDs to their unsigned bit pattern by adding
2^64, preserving the original value in provenance. Original QSO source labels
remain unchanged in the instructor key. No rounded identifiers are created.

Raw DR11 cutouts are cached under
`$BUBBLETEA_EXTERNAL_DATA/bubbletea/teaching/course_packet_v2/`, outside Git.
Use `BUBBLETEA_EXTERNAL_DATA="$HOME/Dropbox/work/data"` on this computer.
Close images are 160 pixels at 0.262 arcsec/pixel (41.92 arcsec square);
context images are 256 pixels at 0.8 arcsec/pixel (204.8 arcsec square).
The layer is `ls-dr11`. Raw failures and discarded alternatives remain cached.
An HTTP success or nonuniform JPEG is not sufficient for a usable source image.

### Rebuild or check the frozen version 2

For wording/style changes, do **not** rerun acquisition or preparation:

```sh
uv sync --extra teaching --extra dev
export BUBBLETEA_EXTERNAL_DATA="$HOME/Dropbox/work/data"
uv run python scripts/teaching/build_part1_materials.py
uv run python scripts/teaching/benchmark_part1_selection.py --pilot
uv run python scripts/teaching/benchmark_part1_selection.py
uv run python scripts/teaching/validate_part1_materials.py
uv run python scripts/teaching/check_part1_answers.py --answers /path/to/student.json
```

The builder requires reviewed image bytes matching their hashes and a matching
reference key. It fails if an image is missing, its review is stale, or the HTML
would exceed 10,000,000 bytes. Validation uses installed Chrome, which is a
maintainer dependency, not a student requirement. Screenshots and synthetic test
answers go under ignored `tmp/teaching/part1/`.

The student-facing [English](../../docs/teaching/project_introduction_en.md) and
[Chinese](../../docs/teaching/project_introduction_zh.md) Project Introductions
have matching three-page PDFs. Rebuild them with
`uv run python scripts/teaching/build_project_introductions.py`, then inspect the
rendered pages in `tmp/pdfs/teaching/project_introduction/`. Font configuration and
Poppler requirements are documented in the
[handoff record](../../docs/development/teaching_materials.md#classroom-finalization-and-project-introductions-2026-10-14).
They introduce the assignment; the interactive activity remains the single HTML.

For a deliberately new data revision, the preparation sequence is:

```sh
uv run python scripts/teaching/prepare_part1_catalog.py --prepare
uv run python scripts/teaching/prepare_part1_catalog.py --acquire --pilot
uv run python scripts/teaching/prepare_part1_catalog.py --acquire
# Inspect every new/changed close and context pair and update the explicit review record.
uv run python scripts/teaching/prepare_part1_catalog.py --review
uv run python scripts/teaching/build_part1_materials.py
uv run python scripts/teaching/validate_part1_materials.py
```

The pilot must pass before expanding acquisition. A changed data snapshot changes
the packet digest and requires a new distribution copy; old answer files must not
be silently reinterpreted. Keep the previous class snapshot for grading.
See the [development record](../../docs/development/teaching_materials.md) for
measured accounting and limitations, and the
[instructor guide](../../docs/teaching/instructor_notes.md) for grading.

## Retained version 1

This is a deliberately selected six-object course snapshot, **not** the scientific
reference catalog, a representative sample, a selector calibration, or a new search.
No canonical source association or classification was edited to create it.

- `targets_v1.json`: exact Gaia identifiers as strings, literature names and
  coordinates, provenance, role, and explicitly assumed host distances.
- `ucd_course_packet_v1.json`: those definitions plus the complete Gaia DR3 query,
  original CSV digest, unrounded measurements, null missing values, retrieval
  timestamps, and twelve image request/scale/digest records.

Objects: M60-UCD1 and M59-UCD3 (known UCD examples), one deliberately selected
foreground comparison, M59cO (compact-system boundary / missing-astrometry example),
and two published candidates. Candidate A, J124352.42+112534.2, is original row 22;
candidate B, J124524.02+110535.2, is row 25 in `reference/liu2015/table6.dat`.
Original Liu and inherited Fahrion source labels differ; the approved reference
state of both classroom candidates remains **candidate**, never confirmed.

Original literature provenance is retained per object: ADS bibcode, DOI, original
table or name, paper URL, and canonical identifier where applicable. The
[source-check record](../../docs/teaching/source_checks.md) explains the independent
M60-UCD1 teaching Gaia identification and the nonrepresentative foreground query.
All external quasar/galaxy/non-single-star catalog memberships are **not checked**.

## External downloads

Raw Gaia CSV and JPEG files are outside the repository. Set
`BUBBLETEA_EXTERNAL_DATA=$HOME/Dropbox/work/data` to use the local project data root;
the configured cache is then `bubbletea/teaching/course_packet_v1/` beneath it.
Otherwise configuration falls back to gitignored `data/external/`.

Gaia endpoint: `https://gea.esac.esa.int/tap-server/tap/sync`.
Legacy Survey endpoint: `https://www.legacysurvey.org/viewer/jpeg-cutout`.
Image layer: **ls-dr11**. Close views: 128 pixels at 0.262 arcsec/pixel, width
33.536 arcsec. Context: 256 pixels at 0.8 arcsec/pixel, width 204.8 arcsec.
Exact URLs, timestamps, content checks, and SHA-256 digests are in the packet.
The UTC download date is 2026-10-12, corresponding to 2026-10-13 local time.

`content_status: nonuniform` rules out a uniform placeholder, not all image defects.
`visual_review_status: pending` is intentional: presentation inspection does not
assign a scientific morphology or contamination label. Preserve the raw packet
when distributing this version; changed snapshots reject old answer imports.

## Reproduce the course files

Only maintainers need these commands. Students need just the generated HTML,
and optionally the PDF; images and data are embedded in the HTML.

```sh
uv sync --extra teaching --extra dev
export BUBBLETEA_EXTERNAL_DATA="$HOME/Dropbox/work/data"
uv run python scripts/teaching/prepare_teaching_data.py --execute --limit 1
uv run python scripts/teaching/prepare_teaching_data.py --execute
uv run python scripts/teaching/build_teaching_materials.py
uv run python scripts/teaching/validate_teaching_materials.py
```

The one-object pilot writes outside Git. Retrieval is serial with bounded retries
and reuses cached responses. The full acquisition writes the teaching JSON only;
do not rerun it just to rebuild wording because its timing metadata changes the
packet digest. For an exact rebuild use the preserved packet and matching caches.
The builder refuses images whose digests differ. The validator uses installed
Chrome; it is a maintainer test dependency, not a student requirement.

Outputs: `docs/teaching/ucd_investigation_v1.html`, `ucd_worksheet.pdf`, and small build /
validation reports. Browser screenshots, synthetic answer files, and PDF page
renders belong under ignored `tmp/teaching/` and `tmp/pdfs/teaching/`, not class
submissions. Paths are centralized in `scripts/config.py`.

For visual PDF QA, with Poppler installed:

```sh
mkdir -p tmp/pdfs/teaching
pdftoppm -png -scale-to 1200 docs/teaching/ucd_worksheet.pdf tmp/pdfs/teaching/page
```

Inspect every rendered page after layout changes. See
[version 1 instructor notes](../../docs/teaching/instructor_notes_v1.md) for the content review,
limitations, and expected calculations. Credits: ESA/Gaia/DPAC and
[DESI Legacy Imaging Surveys](https://www.legacysurvey.org/acknowledgment/).
