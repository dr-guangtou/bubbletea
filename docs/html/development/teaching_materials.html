Teaching materials: implementation and validation

Current checkpoint: 2026-10-14, Part I v2 implemented on teaching_ucd_course_20261012; classroom finalization approved and completed.

Course guide · Instructor guide · Implementation plan · Data and reproduction

This record owns engineering decisions and measured results for the teaching project. Approved requirements live in SPEC, not here. Teaching changes do not alter research selectors, reference classifications, source associations, or radial measurements.

2026-10-14: Part I completed through technical validation

The user authorized autonomous progress after the requirements interview. The implemented deliverable is one offline HTML containing the motivation, neutral Gaia definitions, original scanning illustration, seven labeled examples, three practical tasks, and JSON/text answer handling. An image/evidence audit, separate reference key, and instructor-side checker accompany it. Final pedagogical approval cannot be supplied by the implementation agent and remains the clear next step.

The frontend-design skill informed the editorial reading layout and compact investigation controls. The Legacy Survey API skill informed serial acquisition, provenance, and the distinction between successful transport and usable imaging; the requested teaching release is DR11, not the research review's frozen DR10. An original SVG schematic avoids third-party image licensing or online-video dependencies. No web framework, server, CDN, telemetry, or account is required.

Image and evidence audit

The gallery uses two native image scales: 160 pixels at 0.262 arcsec/pixel and 256 pixels at 0.8 arcsec/pixel. Every retained pair was visually inspected. The review JSON records individual notes and SHA-256 digests. Its statements are teaching-usability judgments, not newly approved research morphology flags or measured centroids. Gaia positions are J2016.0; image exposures span other epochs. Centering was checked visually, not by propagating every source to one assumed image epoch.

Seven initially chosen Cen A objects produced severe colored slabs, stripe-like defects, or obscured central content. For HGHH92-C6, alternative ls-dr11-grz and ls-dr11-south probes did not rescue the display: one was blank and the other retained the color problem. The cause was not established. The DR11 description and known issues were checked; a documented issue is not automatically the explanation for these particular cutouts.

Other rejected introductory images included a blank star cutout, a target hidden by bright-neighbor bleed, a close double, and NGC 3923 UCD1 against a saturated host display. Raw responses remain in the external cache. Two otherwise usable stellar choices had weak motion evidence; the final introductory stellar cards require combined motion significance at least 4. This is a documented pedagogical curation, not a one-dimensional four-sigma probability or a Task 2 stellar cut. Task 2 retains difficult faint/low-motion stars and does not impose image coverage.

The ten Task 1 UCDs now span G = 18.677337646484375–20.079315185546875; four lack Gaia motion solutions. The images remain usable, but the request for bright examples does not justify manufacturing ten G < 19 objects. M59cO is explicitly presented as a UCD/compact-elliptical boundary in the labeled examples only.

Reference identity and provenance were checked against current local audited records. SDSS associations retain their angular separation, and literature sources retain their Gaia-to-adopted-position offsets. The review was not blind to catalog labels, and it is not an independent human classification-success test. Quasars and some UCDs overlap in the supplied measurements. The instructor guide explicitly allows justified uncertainty and identifies Objects 03, 21, and 25 for review. Live SDSS/Archive interfaces are optional and are not claimed to have passed a complete interface rehearsal. Students can complete and submit the activity offline.

Measurement controls: real overlap, not artificial decoys

Task 2 exposes ten genuine measurements with neutral definitions; the five more technical controls are expandable. No fitted selector coefficients, optimized cuts, or artificial random variables are embedded. All cuts start disabled. Simple measured summaries establish that the controls do not all offer the same obvious separation. For example, medians over finite values are:

These instructor summaries are not included as recommended cut directions in the student reading. Missing motion counts above explain why reporting only finite medians is insufficient.

Implementation boundaries

  • prepare_part1_catalog.py assembles observations and the separate key from read-only development inputs; later actions acquire images and attach explicit reviews. Input files and exact identifiers are checked before use.
  • build_part1_materials.py combines the packet, cached images, reading, and scripts/teaching/assets/part1.*; it requires current image reviews and refuses a final HTML at or above 10,000,000 bytes.
  • check_part1_answers.py recomputes selected counts and scores independently with NumPy masks. It reports evidence for manual grading and never assigns a final grade or modifies a student file or research record.
  • validate_part1_materials.py checks data integrity, scoring, file portability, interactions, and browser timing. Temporary screenshots and synthetic answers stay under ignored tmp/teaching/part1/.
  • part1_reading.md owns the student prose. The source HTML/CSS/JavaScript owns task layout and behavior; the generated student HTML is not hand-edited.

All source IDs are strings. Signed FITS SDSS spectrum identifiers are preserved as exact integers and their original representation is retained; no floating-point conversion is permitted. Sampling and presentation use independent hash prefixes to avoid unintentionally grouping classes by their selection rank.

Plots draw every available coordinate pair, not a hidden subsample. Unplottable rows remain in the catalog and denominator. Log-spaced controls save actual physical-unit thresholds; interval endpoints are inclusive. Moving a control does not replace the last evaluated result. History supports up to 500 evaluated attempts, one final selection, and its two explanations after the instructor revision below. Invalid input cannot replace the current answer state. Imported text is rendered literally.

Instructor revisions, 2026-10-14

The revised lesson restores the earlier angular-size control (fixed published M60-UCD1 half-light radius, adjustable hypothetical distance) without simulating an image or using detector sampling as a UCD-detection threshold. Expanded measurement definitions use prominent sans-serif names and plain-language meanings. Native MathML displays the optional equations offline, with readable text equivalents. The detailed Gaia/Aladin/Legacy tool instructions are embedded in a folded section; external text links open new tabs with safe attributes.

Task 1 uses accessible radio controls styled as buttons. Classification alone counts as completion; confidence, evidence basis, notes, and citations are optional. All 37 example/classification cards show Galactic longitude/latitude derived with Astropy from the saved Gaia ICRS coordinates. The frozen catalog, gallery identities, images, classifications, and research inputs are unchanged.

The instructor rejected replacing ranges with weighted scores. Keep the existing range semantics and optimize F1, the harmonic mean of reference-subset purity and completeness. Display all three plus selected class counts and missed UCDs. Unknown candidates remain separate. Empty scored selections have undefined purity and F1 zero. One final attempt replaces the two-list design, with "Why do you think this works?" and "How do you think this selection can be improved?"

benchmark_part1_selection.py first checks 16 combinations, then a bounded grid of 4,536 combinations of G, flux excess, motion significance, and excess-noise ranges. The pilot took 0.127 s and the full trial 0.173 s on this machine. The instructor-only report contains the packet hash, grid, exact rules, counts, controls, and independent scikit-learn F1 verification. Its best tested result is:

The nontrivial solution uses flux excess ≥2.5 and excess noise ≥5 mas, excluding missing active measurements. It is not claimed to be optimal outside this grid, held-out validation, or a new scientific selector. The one-object control is a deliberate teaching diagnostic using the reference label. None of these rules is a preset in the student HTML.

A preliminary ranking experiment motivated the clarification: excess-factor midranks alone gave ROC AUC 0.987552 but average precision 0.526404 on the 20,512 known-class rows. Missing values used neutral midpoint ranks; the ranking was evaluated on the same fixed teaching sample. Average precision is a summary across thresholds, not the purity of a particular list. That approach was not adopted; no scoring-weight UI or AUC-based grade is included. The optional student reading distinguishes ranking evaluation from the range-selected list's F1.

The answer schema is now bubbletea_answers_v3, while the data remain bubbletea_part1_v2 with the unchanged packet digest. A valid same-packet v2 import must reproduce its original metrics before F1 is added. It retains all responses, attempts, and prior final choices, while asking the student to choose the new final selection and write the new explanations. Browser and independent instructor-checker migration agree; malformed old scores do not replace saved work.

New browser checks verify every derived Galactic coordinate, button completion, external-link behavior, folded guide, offline equations, the distance control's inverse-distance scaling and keyboard input, and instructor-trial counts/F1. The full page still makes zero mandatory network requests. Native equations, definitions, button controls, object cards, final selection, and plots were visually inspected. Windows, other browsers, and screen readers remain untested; there is no hidden deployment or remote typesetting dependency. The linked build and validation reports contain the final exact sizes and timing measurements.

HTML code review and Student ID wording, 2026-10-14

The requested label is now Student ID in the submission panel and readable export. The JSON key remains student_identifier, preserving existing answers. Only this wording and its regression check were changed; the behavior changes below are proposed fixes, not implemented in this review. The approved visual design and frontend styling remain intact.

The review inspected the HTML template, JavaScript, CSS, builder, independent instructor checker, and validation coverage. Reproductions used isolated offline Chrome contexts and synthetic answers, never real student browser storage.

High priority: rejected imports can replace current in-memory answers

validate_state() checks attempt identifiers with a regular expression without first requiring a string. JavaScript converts ["attempt_0001"] into the string "attempt_0001" for this check, so a one-element array can pass. The import handler then assigns state = candidate before rendering. render_history() calls the identifier's .replace() method, which an array does not have. The catch message says the import was rejected and current answers were kept, but the in-memory state and already-updated fields now contain the incoming file's answers.

Reproduced from one valid evaluated attempt with an empty final choice: change task2_attempts[0].attempt_id to ["attempt_0001"], change the incoming ID/evidence, and import the file. The original ID was original_student; after the reported rejection, the active ID was incoming_student and the evidence was replaced. The previous local-storage draft remained intact because rendering failed before persist(). No on-disk submitted JSON was changed, but subsequent editing could overwrite the browser backup too. The independent Python checker rejects this array identifier; browser and checker validation currently disagree.

Recommended fix: require string attempt identifiers, reject wrong types before changing state, and restore the previous state/UI if applying an import fails. Add the array-identifier case and an apply-stage failure to regression checks. This is a blocker to freezing the classroom copy.

Medium priority: malformed numeric input silently removes a cut

In build_rule_controls(), the numeric-field handler treats input.value === "" as an intentional unbounded endpoint. A browser also exposes an empty value when a number field contains an incomplete number such as -, while setting input.validity.badInput to true. The handler does not distinguish these states.

Reproduced with an enabled G maximum of 19: select the numeric text, type -, leave the field, and Evaluate. The saved maximum becomes null with no error. The selected count increases from 12,901 to 21,118. Counts are internally consistent with the now-unbounded rule, but the student's malformed entry has silently broadened the selection.

Recommended fix: check native numeric validity before accepting an empty value, retain the last valid bound on malformed input, and make the warning clear. Test invalid exponent/sign input separately from an intentional blank. This is also a blocker to freezing the classroom copy.

Medium priority: the keyboard-accessible table omits a plotted measurement

The brightness/excess-noise canvas points users to equivalent records in the accessible table. render_catalog_table() supplies only ID, G, BP−RP, flux excess, parallax significance, and motion significance; astrometric excess noise is missing. A student who cannot use hover cannot inspect that plot's numeric vertical coordinate through the promised alternative.

Recommended fix: include every plotted quantity in the table, with units and missing-value handling, and check that plot fields are a subset of table fields. No class labels need to be added.

Lower priority: point-selection text can be stale after evaluation

The hover line updates on mouse movement, but render_results() redraws plots without updating or clearing that line. In an all-source selection, hover showed Gaia 772819441531617408 as selected. Evaluating a G range of -1 to 0 then selected zero objects, while the line still described that source as selected. The plot and counts were correct; the textual selection status was stale.

Recommended fix: clear the hover description when the evaluated selection changes, or retain the hovered row index and refresh its status from the new mask. Test evaluation and answer-file restoration after hovering.

Lower priority: logarithmic slider endpoints can exclude the maximum row

The slider maps through log1p and its inverse even at the endpoints. Round-trip floating-point error can produce a maximum just below the observed maximum, so the advertised inclusive range excludes the highest-valued row. The affected fields in the frozen packet are flux excess, motion significance, astrometric excess noise, and excess-noise significance. Their endpoint differences are tiny, but the comparison uses exact numeric values, not the rounded displayed labels.

Recommended fix: use the stored observed minimum/maximum exactly at slider positions 0/1000, and interpolate only interior positions. Do not introduce an arbitrary scientific tolerance into all range comparisons. Test the handler with all features, checking that full observed ranges retain all finite rows.

Classroom finalization and Project Introductions, 2026-10-14

Implemented and verified:

  1. Require primitive string attempt identifiers before regex validation. A failed import application restores the previous in-memory state and redraws the previous form/history/results; browser storage is not written before that application succeeds. Tests reject array IDs in both v3 and migrated v2 and force a rendering-stage failure after an otherwise valid import.
