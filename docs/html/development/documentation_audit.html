Documentation consolidation audit

Date: 2026-10-12
Original checkpoint: 9dd2569
Scope: Documentation organization only; no scientific data or classification changes.

Documentation guide · Science guide · Current status

Decisions

  • Keep six project-level Markdown documents directly in docs/: SPEC, PLAN, current status, issue register, documentation guide, and science guide.
  • Move permanent feature, contaminant, catalog, and radial definitions to methods/.
  • Merge 42 development reports into ten topic records. Preserve each report's unique scientific content and original-date limitations in a labelled section; the section wrappers distinguish past decisions from current reading guidance.
  • Retire the July CONTEXT entry point into project history. Its stale setup and next-step instructions are no longer recommended; current status replaces that role.
  • Remove the 47 old standalone files only after their content is retained below. No unique measurement or provenance is deliberately discarded. Git retains the original checkpoint, and the register stores original source hashes.
  • Keep journals and lessons unchanged. Existing historical path citations can be resolved with this table and the HTML renderer's migration register.
  • Keep the unreferenced HSC example image and legacy SQL in development assets, not at the project-document level. They are historical examples, not active pipeline inputs.
  • Place the HTML entrance at docs/index.html and all generated pages/assets at docs/html/. Remove the obsolete root index and root site copies.
  • Future development notes extend these topic records instead of creating another top-level report. This rule is persisted in AGENTS.md and CLAUDE.md.

Closeout preservation correction

The 2026-10-12 closeout adds a new journal and appends a lesson; it does not rewrite historical journals or lessons. The validator now checks each original journal byte-for-byte and requires the original lesson bytes to remain an unchanged prefix, while allowing new files. The former directory-wide diff would incorrectly reject normal additions. Rebuild the portal after each addition; current source/page counts and navigation results are recorded in docs/html/build_report.json.

Disposition of every relocated or merged Markdown document

The five existing project-level owners were retained: PLAN.md (roadmap), SPEC.md (approved requirements), current_status.md (dated status), todo.md (issues), and documentation_guide.md (organization). The sixth, science_guide.md, is a new plain-language reading map, not a competing specification.

“Merge” removes the former standalone file but keeps its content in a dated section. “Relocate definitions” preserves a permanent scientific explanation below methods. “Retire entry point” keeps the old context only as historical evidence.
